# MUT Shuttle Bus · MiniProject

ระบบรถรับส่งมหาวิทยาลัย: React + Vite, Express และ Oracle

## หน้าจอ

ปรับโทนฟ้า–ชมพูตามภาพอ้างอิง พร้อมเมนูด้านล่างบนมือถือและเมนูด้านข้างบนคอมพิวเตอร์

- ผู้โดยสาร: เลือกจุดขึ้น–ลง / วันที่ / 1–4 ที่นั่ง, เลือกหลายรอบ, ยืนยันการจอง, ตั๋ว QR ที่บันทึกเป็นรูปภาพได้, ประวัติ และหน้าต่างยกเลิกรายการ
- คนขับ: ตารางงาน, เริ่มรอบ, รายชื่อผู้โดยสาร, แผนผังจุดจอด, ตรวจ QR ก่อนยืนยันขึ้นรถ, ยืนยันลงรถ และสรุปปิดรอบ
- ผู้ดูแล: จัดการผู้ใช้, สวิตช์สิทธิ์ตามตำแหน่ง, เส้นทางและจุดจอด, ตารางเดินรถ, แผนกและรถ
- การจองต้องล่วงหน้าอย่างน้อย 20 นาที คำนวณเวลาออกในเขตเวลาไทย ตรวจซ้ำบนเซิร์ฟเวอร์
- หน้าแผนผังแสดงลำดับและเวลาเดินทางตามข้อมูลเส้นทาง ยังไม่มี GPS หรือเวลาถึงจริงใน schema ปัจจุบัน
- รายงาน SC05 ยังเป็นหน้ารอพัฒนาจากโครงการเดิม

## เปิดใช้งานกับ Oracle

ในโฟลเดอร์ `server`:

```powershell
npm install
npm start
```

ในโฟลเดอร์ `client`:

```powershell
npm install
npm run dev
```

เปิด URL ของ Vite และล็อกอินด้วยบัญชีจากตาราง `USERS` ไม่มีบัญชีสำรองอัตโนมัติเมื่อฐานข้อมูลล่ม
Vite ส่ง `/api` ไป `http://127.0.0.1:5000` โดยกำหนด `API_TARGET` เพื่อเปลี่ยนปลายทางได้
เมื่อใช้ production build ต้องตั้งค่า reverse proxy `/api`, SPA fallback และ HTTPS

`server/db.js` อ่าน `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_SERVICE` จาก `server/.env`
รูปแบบการเชื่อมต่อคือ `host:port/service` โดย DB_HOST ต้องเป็น host หรือ IP เดียว
ตรวจยืนยันการเชื่อม Oracle จริงแล้วเมื่อ 6 ตุลาคม 2569: ตำแหน่ง 3 รายการ แผนก 3 รายการ และหน้าจอ 11 รายการ นำตำแหน่ง P4 ชื่อ “ทดลองระบบ” ที่ไม่มีผู้ใช้อ้างอิงออกแล้ว

## แหล่งข้อมูลและ API

หน้าจอที่ใช้งานจริงอ่านข้อมูลจาก API ของ Express:

- `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`: cookie session
- `GET /api/directory`: รหัส ชื่อ นามสกุล ตำแหน่ง และรหัสแผนก
- `/api/users`: อ่าน เพิ่ม แก้ไข และลบผู้ใช้ สำหรับตำแหน่งที่มีสิทธิ์ SC01 ตามตาราง PERMISSION
- `GET /api/shuttle`: รถ เส้นทาง ตารางเดินรถ การจอง และสิทธิ์จาก Oracle
- `POST /api/shuttle/actions`: ตรวจสิทธิ์และกฎการทำงานก่อนเขียนข้อมูลใน transaction

`server/shuttle.js` จัดการ mapping สถานะและตาราง Oracle; `shared/shuttle.mjs` รวมกฎการจองและสถานะ
`client/src/lib/useShuttle.js` โหลดข้อมูลทุก 15 วินาที และรอผลบันทึกก่อนอัปเดตหน้าจอ
ข้อมูลจำลองอยู่เฉพาะ `shared/test/fixtures.mjs` สำหรับชุดทดสอบอัตโนมัติ นำเซิร์ฟเวอร์ทดลองและที่เก็บข้อมูลตัวอย่างออกจากแอปแล้ว ไม่มีบัญชีทดลองให้เข้าสู่ระบบ
ไฟล์รุ่นเก่าบางไฟล์ใน `client/src` ยังคงอยู่ แต่หน้าจอปัจจุบันนำเข้าจาก `client/src/pages`

รหัสผ่านไม่ปรากฏใน API อ่านผู้ใช้ การแก้ไขเว้นว่างเพื่อคงรหัสเดิม และรหัส/เบอร์โทรเก็บเป็นข้อความ
ระบบป้องกันการลบหรือเปลี่ยนตำแหน่งของบัญชีที่กำลังใช้งาน แต่สวิตช์สิทธิ์ทุกเมนูเปิด–ปิดได้ทุกตำแหน่ง รวมถึง SC01 และ SC02 ของตำแหน่งตนเอง
Session ใช้ HttpOnly/SameSite cookie อายุ 8 ชั่วโมง เก็บในหน่วยความจำและหมดเมื่อ restart
การเปลี่ยนรหัสผ่านจะยกเลิก session ของผู้ใช้คนนั้น การตรวจรหัสผ่านยังเข้ากันกับ schema เดิมและยังไม่ได้ย้ายเป็น password hash

กล้องเปิดเมื่อผู้ใช้กดปุ่มเท่านั้น ต้องใช้ HTTPS หรือ localhost และอนุญาตกล้อง
ระบบหยุดกล้องเมื่อเปลี่ยนหน้า ซ่อนแท็บ หรือพบ QR ที่รอการยืนยัน รองรับกรอกรหัสแทนกล้อง

## สิทธิ์ ตำแหน่ง และแผนกจากฐานข้อมูล

- รายการตำแหน่งใช้ตาราง `POSITION` และแผนกใช้ `DEPARTMENT` โดยตรง การเพิ่ม แก้ไข และลบทำผ่าน Oracle transaction
- สวิตช์ทุกตัวใช้ `PERMISSION` ไม่มีข้อยกเว้นสำหรับ P1/P2/P3 ทั้งฝั่งเมนูและ API
- ผู้ที่มีสิทธิ์ SC02 สามารถกำหนดสิทธิ์ของทุกตำแหน่งและจัดการตำแหน่งได้
- ผู้ที่มีสิทธิ์ SC10 สามารถจัดการแผนกได้ ผู้ที่มี SC11 สามารถจัดการรถและประเภทรถได้
- หากปิด SC02 ของตำแหน่งตนเอง จะเข้าหน้ากำหนดสิทธิ์ไม่ได้จนกว่าตำแหน่งอื่นที่มี SC02 จะเปิดให้ หรือผู้ดูแลฐานข้อมูลแก้ใน PERMISSION
- ป้องกันการลบแผนกหรือตำแหน่งที่มีผู้ใช้อ้างอิงเพื่อรักษาข้อมูลในฐานข้อมูล

สคริปต์ `server/scripts/migrate-permissions.cjs` บันทึก SC10/SC11 ที่เดิมเป็นเมนูเสมือนลง SCREEN และคงสิทธิ์เดิมของ P1 เฉพาะเมนูที่เพิ่งสร้าง พร้อมลบตำแหน่งชื่อ “ทดลองระบบ” เฉพาะเมื่อไม่มีผู้ใช้อ้างอิง ทำใน transaction เดียว และรันซ้ำได้โดยไม่เปิดสิทธิ์ที่เคยปิดกลับมา
สคริปต์นี้ดำเนินการกับฐานข้อมูลที่ตั้งค่าไว้แล้วเมื่อ 6 ตุลาคม 2569

สำหรับฐานข้อมูลชุดอื่นที่ยังไม่ได้ปรับ ให้รันจากโฟลเดอร์ `server`:

```powershell
node scripts/migrate-permissions.cjs
node scripts/check-schema.cjs
```

ชุดทดสอบล่าสุด: client 11 รายการ และ server 23 รายการ ผ่านทั้งหมด พร้อม lint และ production build

## การเพิ่มผู้ใช้และแก้ไขบัญชีส่วนตัว

- หน้าเพิ่มผู้ใช้แสดงรหัสถัดไปอัตโนมัติ เช่น U007 โดยอ่านจาก USERS รหัสที่แสดงเป็นตัวอย่างก่อนบันทึก และเซิร์ฟเวอร์จะกำหนดรหัสจริงใน transaction ที่ล็อกการเพิ่มพร้อมกันเพื่อป้องกันรหัสซ้ำ
- รหัสที่ส่งมาจากฟอร์มไม่สามารถกำหนดทับรหัสของบัญชีเดิมได้ ระบบแจ้งรหัสที่บันทึกจริงหลังเพิ่มสำเร็จ
- สุ่มรหัสผ่าน 6 ตัวอักษรด้วย Web Crypto มีตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก ตัวเลข และอักขระพิเศษ สามารถสุ่มใหม่ แก้ไข และแสดง/ซ่อนได้ รหัสผ่านใหม่ต้องมี 6 ตัวอักษรเท่านั้น
- ทุกบัญชี รวมคนขับและผู้ใช้ทั่วไป เข้า **บัญชีของฉัน** (`/profile`) จากเมนูหรือไอคอนผู้ใช้มุมบน เพื่อแก้ไขชื่อและนามสกุลที่บันทึกลง USERS
- เปลี่ยนรหัสผ่านโดยกรอกรหัสผ่านปัจจุบัน รหัสผ่านใหม่ และยืนยันรหัสผ่านใหม่ หากเปลี่ยนเฉพาะชื่อให้เว้นช่องรหัสผ่านทั้งหมดว่าง
- API ใช้บัญชีจาก session เท่านั้น ไม่รับ userId/ตำแหน่ง/แผนกจากฟอร์มแก้ไขบัญชีส่วนตัว เมื่อเปลี่ยนรหัสผ่านสำเร็จจะออกจากระบบใน session เก่า และต่ออายุ session ของหน้าที่กำลังใช้งาน
- API ที่เพิ่ม: `GET /api/users/next-id` (ต้องมี SC01), `PUT /api/auth/profile` (ต้องเข้าสู่ระบบ)
- ไม่ต้องเปลี่ยนโครงสร้างฐานข้อมูล การทดสอบเพิ่ม/แก้ไขบัญชีใช้ข้อมูลแยกในชุดทดสอบ ไม่แก้ไขชื่อหรือรหัสผ่านของบัญชีจริง ตรวจ Oracle แบบอ่านอย่างเดียวแล้วว่ารูปแบบรหัสและขนาดคอลัมน์รองรับ
